# FRPHI — 手机上的 Phira 制谱器 APK

把"打歌"变成"制谱"：导入音乐和背景图，填好曲名/BPM/难度，跟着音乐在设备上敲击，
每一根手指的操作自动转成 Tap / Hold / Flick 音符，一键导出 **.pez** 谱面包，
可直接放进 **Phira** 或 **Re:PhiEdit** 游玩/继续编辑。

## 判定线 / 图片 / 文字缩放 & 资源包管理（1.10.12）

**缩放**
- 判定线编辑时，右上角输入面板新增「缩放」：默认 `1`，`<1` 缩小、`>1` 放大；图片/文字/普通判定线都生效。
- **缩放是逐关键帧的**（和位移/旋转/流速/透明度一样）：所有关键帧各自带一份 `scaleX/scaleY`，
  帧与帧之间线性过渡，导出写进 RPE 的 `extended.scaleXEvents / scaleYEvents`，每个关键帧管到下一个关键帧。
  - 选中了关键帧（左侧红框）或刚打完帧 → 改缩放**只改这一帧**；
  - 没选帧 → 改的是**此刻正在生效的那一帧**（`time ≤ 当前时间` 的最后一帧）⇒ 看到的就是哪一段被改；
  - 整条线一帧都没有 → 改的是整条线的基准缩放。
  - 以前写入端会把新值刷进**每一帧**（改一次缩放，全曲所有关键帧被改成同一个值），
    读取端在编辑时又只认基准值 —— 这就是"缩放加不进关键帧、一改就全部应用"的原因，已修掉。
- 打关键帧会把**此刻画面上的**缩放/透明度一起钉住（以前透明度被写死成 100%，在淡入淡出中间打一帧会把渐变打断）。
- 画布上的编辑方框四周新增 4 个向外的绿色箭头（上/下/左/右），拖动即可等比缩放；
  白色箭头仍然是旋转，菱形仍然是打关键帧。判定线上的移动/旋转/缩放/关键帧按钮**不参与触摸兼容放大**
  （左侧时间轴上的关键帧点仍然参与，方便兼容模式点选）。
- 图片线的「1」仍然是"宽度铺满谱面"的默认大小；导出/草稿继续写 RPE 的 `scaleX/scaleY`，与旧包兼容。
- 判定线编辑期间，右侧判定线窗口**时刻用红框框住正在编辑的线**；从画布长按进入编辑后再打开窗口也会框住。
  在这种状态下点窗口背景会**直接收起窗口**，不再要求先取消框选再点第二次。

**双押贴图（`*_mh.png`）**
- `click_mh / flick_mh / drag_mh`：普通贴图**原尺寸居中** + 外圈金色光晕，画布 = 普通尺寸 + 150
  （与 Phira 默认包同尺寸，宽度比 1.15 全部是光晕留白）⇒ 双押音符的**本体与普通音符逐像素同大**。
- `hold_mh`：画布 = `hold.png 宽 × 1.15`（1150×1100，**高度与 hold.png 相同**），
  本体原尺寸水平居中，**不加任何光晕/描边** —— 双押长条与普通长条完全一样大。
  原因（Phira `prpr/core/note.rs`）：Phira 画音符的宽度倍率取 `click_mh/click`（≈1.1503），
  **对长条同样生效**，并把整张贴图拉伸到这个宽度。所以长条的双押贴图必须 1.15 倍宽、
  本体居中，Phira 里本体才是 1.0003 倍（视觉相同）；上一版"与 hold.png 同画布"会被
  Phira 整体放大 1.15 倍，体内的金线/光晕全跟着被放大（用户实测：大小完全不对、
  光晕渲染在放大的长条内部）。高度不能动 —— FRPHI 是整张贴图拉伸到长条高度，
  上下留白会把本体压短。长条因此**不做双押提示**（和普通长条一模一样）。
- 以前这套 `*_mh` 是把普通贴图整张放大 1.15 倍再塞进画布，本体变大、两端还被画布裁掉，
  于是双押音符永远比普通音符大一圈；重新生成后 `*_mh` 合计 261 KB → 144 KB（APK 少 117 KB）。
- 生成脚本：`docs/make_mh_notes.py`（改完普通贴图后重跑一次即可）。
- 代码侧兜底：`texScale()` 拿不到双押/普通贴图的比例时按 **1** 处理（旧版写死 1.15，会把音符放大 15%）。

**资源包窗口**
- 资源包条目支持上下拖动排序（长按后拖；自带包也能拖），顺序会保存。
- 右滑任意资源包（含自带包）弹出「资源包操作 / 取消 / 复制 / 导出」，样式与「谱面操作」一致；
  复制出来的包放在**所有资源包最后**，自带包复制会先把内置贴图/音效落盘再复制。
- 左滑导入的资源包会删除；**自带包左滑不会被删除**，松手弹回原位。
- 长按顶部「＋」新建空白资源包项目，放在最后；长按资源包条目进入资源包项目页（当前留空，按返回退出）。

## 图片线 / 文字线（素材判定线，1.10.11）

判定线抽屉右下角「＋ 新建判定线」支持两个手势（和"行上"左复制/右删除同一套方向语义）：

- **左滑** = 选一张图片当判定线（RPE 的 `Texture` 指向包内 png）
- **右滑** = 新建文字线（RPE 的 `extended.textEvents`，Phira 用自带字体渲染）

**命名规则（和 Phiedit / Phira 一致，修掉了旧命名混乱的来源）**：
- `Line.name`（RPE `Name`）**永远只放自动名 `lineN`**，类型只体现在 `Texture` / `textEvents` 上，
  绝不把"图片/文字"写进 Name；界面标签按类型显示：`图片线 3` / `文字线 3`，带自定义名的导入线显示 `名字（文字）`。
- 图片复制进 `filesDir/lineimg/`，草稿只存文件名（`LP` 行），导出按名字打包进 `.pez` 根目录；本地路径不落盘、联机同步也不带。

**行为**：
- 新建的图片线/文字线**默认生成在屏幕正中间**（posPct=50），再随便拖走。
- 「＋ 新建判定线」的左滑/右滑现在都和剪贴板一样：**滑的时候就铺绿色背景**（滑得越深越绿），
  不再"左=绿/右=橙"地给按钮换颜色；默认不再显示"左滑 图片 右滑 文字"这行提示，松手时在页脚显示"松手新建图片线 / 文字线"。
- **长按图片/文字的实际显示区域也能进入判定线编辑**（图片线/文字线本体只是一条细线，不需要正好按在那条线上，
  按在图中间、文字中间都行；抽屉里左滑复制这类素材线只显示一个"复制"圈——它们本来就带不了音符）。
- 图片线默认按"宽度铺满谱面视口"算 scale（RPE 里图按"1 像素 = 1 单位"画在 1350×900 坐标系），之后可用 rpe-next 微调。
- 文字线的字号由 Phira/Phiedit 的设置决定（谱面里只有 `scaleX/scaleY`），预览取 Phiedit 默认 50；
  新建文字线的输入框占位改为"输入文字"，新建对话框标题就是"输入文字"（修改时仍叫"修改文字"）。
- **素材线上不能放音符**（点空白会提示；粘贴、AI、连续铺的所有路径都在 `addNote` 兜底拦截）。
- 图片/文字线照常支持：拖动、旋转、透明度、关键帧、父线、框选、撤销（快照含新字段）、复制（类型同步复制）。
- 导出时图片文件若丢失自动退回 `line.png`，不会导出指向空文件的坏包。
- 导入 `.pez` 时读回 `Texture` / `textEvents` / `scaleX/scaleY`，并把贴图从包里抽出来。
- 单测：`DraftLineNameTest` 新增"图片/文字线草稿往返不丢类型"、"老草稿不会误判成素材线"。

## 判定线编辑：关键帧交互（1.10.11）

- **点关键帧 = 进入关键帧编辑**：左侧时间条上的关键帧点一下，就把它**框住（红框）**并选中，
  右上角输入面板（角度 / X / Y / 流速 / 透明度）和拖线、拖旋转箭头都改这一帧；再点同一个关键帧 = 删除它。
- **打完关键帧不用先搓时间轴就能直接改这一帧**：点"关键帧小方块"（或点判定线任意位置）打帧后，
  当前帧立刻变成编辑目标，直接拖判定线 / 转角度 / 改流速 / 改透明度都会**写进这一帧**（以前必须先旋转线再打帧，
  打完之后手拖还改不动当前帧）。
- **退出就保存**：滑动左侧时间轴或点背景退出判定线编辑时，先把右上角输入框里的数值写回当前帧/当前线，
  再退出关键帧编辑；帧的姿态与输入框信息都不会丢。右上角输入框显示"帧 x.xx s" = 现在改的是这一帧。

## 音符列表 / 单音符属性面板（1.10.11）

「更多」→「编辑」里新增 **音符列表** 开关（`btnNoteInfo`，默认 **关闭**，状态和音效/全量模式一样落盘），
按钮位置在 **「全量模式」右边**（「自动移动」下面那一格，和「全量模式」同一行）。

**1. 开关打开后，"点红框里的音符"从"删除"变成"弹面板"**
- 关闭时（老行为）：点红框里的音符 = 松手没拖动就删掉整组。
- 打开时：**不删**，改为在音符**右侧**弹出面板（右边放不下自动翻到左边，再夹进屏幕）。
  点面板外面的任何地方关闭；键盘弹出时面板会跟着变矮（`adjustResize`），不会被键盘顶出屏幕。
- 第一次点某个音符仍然只是"框住它"，再点一下（或直接点已框住的）就出面板 —— 框住一**群**音符
  时点其中任意一个，面板改的是**全部**被框住的音符。

**2. 面板布局：第一列操作，第二列属性**

| 列 | 内容 |
|---|---|
| 第一列 | **删除**（删掉整组，一次撤销步）/ **X镜像**（沿判定线中心左右翻，同 Phiedit 的 Alt+A）/ 关闭 |
| 第二列 | 类型、方向与真假、时间、X 坐标、速度、大小、透明度、纵向偏移、可见时间、判定范围、音符颜色、特效颜色、打击音效 |

**3. 属性表：和 Phiedit `NoteEditPanel` 一一对应**

| 面板字段 | RPE 字段 | 说明 |
|---|---|---|
| 类型 | `type` | 蓝键/长条/红键/黄键；蓝↔长条时自动补一个格的 `endTime`（`pass` 跟着改） |
| 正面/反面 | `above` | 整组设为同一面 |
| 真/假音符 | `isFake` | |
| 起 / 止 | `startTime` / `endTime` | 毫秒；"止"只对长条生效 |
| X | `positionX` | 面板显示 RPE 像素（-675~675），内部存归一化 `posX` |
| 速度 | `speed` | 音符级下落倍率（乘在判定线流速上） |
| 大小 | `size` | 横向倍率 |
| 透明度 | `alpha` | 面板 0~255，内部 0~1 |
| Y偏移 | `yOffset` | RPE 像素 |
| 可见时间 | `visibleTime` | 秒，999999 = 一直可见 |
| 判定范围 | `judgeArea` | 只写进谱面（Phira/Phiedit 判动用），本机预览不判定大小键 |
| 音符颜色 | `tint` | 面板填 `R,G,B` 或 `#RRGGBB`，空 = 原色；渲染按正片叠底上色 |
| 特效颜色 | `tintHitEffects` | 同上 |
| 打击音效 | `hitsound` | 循环按钮：默认 → tap.mp3 → drag.mp3 → flick.mp3 |

> **没有"角度"这个字段**：RPE / Phiedit 的音符本来就没有旋转属性（能转的是判定线和 `incline` 倾斜），
> 所以这里也没造一个导不出去的假字段。要"角度感"就用 X 坐标 + 判定线角度。

**4. 多选：改全部被框住的音符**
- 数值字段上面有个 **设为 / 增减 ±** 开关：`设为` = 全部改成这个值，`增减` = 每个都在自己原值上加这个数。
  透明度按 0~255 加减，X 坐标按 RPE 像素加减。
- **时间**永远按"差值整体平移"：`设为` 把选中的第一个音移到这个时间、其余保持相对位置；
  `增减` 就是整组前后平移这么多（不会把一堆音符压到同一时刻）。
- 属性值不一致时输入框**空着并提示"混合"**，不动它就不会被改（避免"只想改透明度结果把速度也写回去了"）。
- 整批改动是**一个撤销步**（`applyNoteInfo` 内部开一个事务），点一次"应用"就能整体撤回；
  每个字段在比较时有 epsilon（如 X 差 < 0.0003、时间差 = 0），只点应用不改值不会产生空的历史记录。

**5. 顺带补齐的单音符属性（Phiedit 有、之前导出会丢的）**
- `RecordedNote` 新增 `judgeArea / tint / tintHit / hitsound`，四者都是"有值才写"：
  草稿 `N` 行在 `spd yOff a size visT` 之后追加 4 个字段（老版本读多字段会忽略、读 13 字段仍按默认值），
  导出 `.pez` 时写 `judgeArea` 恒有、`tint`/`tintHitEffects`/`hitsound` 有值才写；导入时反向读回（也认 Phiedit 的旧字段名 `color`）。
- 单测：`DraftCodecTest` 里新增"扩展属性往返"与"只有 13 字段的老草稿仍能读"两组。

## 导入视频提取音轨：改成后台 + 进度条弹窗

- 以前：选完视频回到界面就在 **UI 线程**上跑 `MediaExtractor/MediaCodec` 解码，几秒钟界面完全没反应，
  用户不知道它在干嘛（看起来像卡死）。
- 现在（`MainActivity.handleAudioPicked / showExtractDialog / runExtract`）：
  1. 回到界面先在后台线程探测是不是视频（`probeVideo`：0 普通音频 / 1 视频有音轨 / 2 视频没音轨），
     普通音频直接应用，视频没音轨直接提示，都不卡界面；
  2. 视频 → 弹 **「提取音轨」** 弹窗（和「导入谱面」同一套样式：标题 + 进度条 + 百分比 + 取消 / 确认，
     确认在跑完之前是灰的），解码全程在后台线程；
  3. 进度 = 已解码时间 / 音轨总时长（`KEY_DURATION`），每变 1% 才回一次 UI；
     拿不到时长就转圈（indeterminate），不猜；
  4. **取消**会立刻停掉 codec、删掉半截 wav；提取成功之后「取消」自动变灰，
     免得把已经是项目音乐的 wav 删掉。

**3. 本地 BPM 检测（BPM Detect，不联网）**
- 主界面「判定线位置」输入框右边新增 **检测 BPM** 按钮；分析时弹进度条（和导入谱面同一个弹窗样式），
  可取消；完成后弹结果：**一键应用**（只改 BPM）/ 连偏移一起 / 取消。
- 算法是 Kotlin 重写（参考 SoundTouch 的 `BPMDetect`、aubio 的 tempo、librosa 的流程）：
  PCM → 10ms 一格的低频/全频能量 → 起音包络 → 60~200 BPM 逐候选做"节拍梳"打分 → 先验 + 倍频校正。
  解码仍然只用系统 `MediaCodec`，**零第三方依赖、音频不出手机**。
- 拍长取整到整数 BPM，顺带给出「首个重拍」（可以顺手填 BPM 偏移）。
- 实测量化（`BpmSignalTest`，合成鼓点：底鼓 55Hz + 八分音符镲 + 底噪 + 持续和弦）：

  | 真实速度 | 检出 | 备注 |
  |---|---|---|
  | 70 / 85 / 100 | 70.0 / 85.0 / 100.0 | 慢歌不翻倍 |
  | 128 / 140 / 160 | 128.0 / 140.0 / 160.0 | |
  | 170 / 180 | 170.0 / 180.0 | 不会被判成 85 / 60 |

  > 踩过的坑：① 只取单格取样会因为"差半格"漏掉整拍 → 改成 ±1 格取最大；
  > ② 梳状打分天生偏爱慢（周期越长越容易只吃到最强的重音）→ 加 2× / 3× 倍频校正；
  > ③ 相位在 ±1 格内会打平，几千个相位平手时取最靠前的，避免"首个重拍"跑到 590ms。

  跟着项目标签一起落盘（`TabData.bpmSegments`，格式 `0:222|17568:146.5`），进编辑页/回主界面都不丢。
- **导出**时原样写回 `BPMList`（每段 `bpm` + `startTime` 拍数），并且**音符/关键帧的时间按分段换算成拍**

  （d=1 那档 `round(0.57)=1` 被误判成"进位"），多 BPM 导出时音符会整体偏 128~175ms。

**5.2.1 大谱面导入修复（"压缩包里没有找到谱面 JSON"）**
- 根因：所有文本条目共用一个 **8MB** 上限，而 RPE 的 json 是带大量缩进的美化格式——
  一条 55~56 线、1.6~2.7 万事件的谱面，json 就有 **8.6MB / 13.7MB**，超限后整条被丢掉，
  于是报"没有找到谱面 JSON"（而在 Phira/Phigros 里完全正常）。
- 修：json 单独放宽到 **64MB**（info.txt 等小文本仍限 2MB）；解析前先**去掉缩进**（13.7MB → 5.4MB，
  解析更快、内存省一半）；超过 64MB 时给准确提示；`AndroidManifest` 加 `largeHeap` 兜底。
- 顺带修：判定线关键帧超过上限时，以前是"截断"（动画放到一半定住），现在改成**均匀抽稀**（保留首尾）。

**5.3 编辑手感 / 素材显示 / 打歌缩放**
- **拖进度条谱面实时跟随**：拖动时只改"预览时间"（`editSeekOffset`），谱面跟着手指走；
  松手才真正 `MediaPlayer.seekTo`，并等播放器到位后再撤掉预览偏移（不会出现滑块被拽回去、画面弹一下）。
- **长按「撤销」= 重做**：加了标准的"撤销/重做"两栈（`redoStack`）。
  撤销时把"改写成了什么"回填进 `UndoEntry`（音符新旧值 + 判定线快照前后值 + 剪贴板前后值），重做就是正向重放；
  一旦有新改动 / AI 整谱替换 / 载入草稿，重做栈自动清空。
- **素材显示真实文件名**：`content://…/audio:1234` 这种以前直接把 ID 显示成"音频：audio1234"，
  现在查 `OpenableColumns.DISPLAY_NAME`；视频提取的音轨用**视频的名字** +「（已提取音轨）」。
- **Autoplay 用 Phira 游玩缩放**：进入打歌时把缩放切到 `判定线位置% × 0.045`
  （推导：`distPx = ∫speed dt × 0.16 × h/720 × scale`，令 1 秒的落谱正好铺满判定线上方那段高度），
  与分辨率无关；退出 AUTOPLAY 后恢复你上次的自定义缩放并同步右侧「缩放」输入框。

## v0.21.0 性能优化（导入大谱面不再卡）

大谱面卡在"每帧重复计算"，不是解压/解析 pez。逐项修掉，并加了 JVM 基准（`app/src/test` 里会打印）：

| 问题 | 原来 | 现在 |
|---|---|---|
| 双押检测 `doubleHintIdx` | 未判定音符两两比较 **O(n²)**，每帧跑一次 | 按时间排序后滑窗 + 只处理屏幕附近的时间段 |
| 判定线姿态 `linePoseAt` | 每次调用 `sortedBy{}` 新建列表并排序；每个音符要调 2 次 | 关键帧排序缓存 + 二分，每帧只算 1 次并传给绘制 |
| 音符绘制循环 | `withIndex()` 每帧分配 n 个对象；每音符重算姿态 | `for (i in notes.indices)`，姿态/中心/旋转作为参数传入 |
| 草稿序列化 | org.json 逐条建对象（UI 线程） | `DraftCodec` 逐行文本，导入时在后台线程写 |
| 草稿解析 | onCreate 同步 org.json 解析 | 后台解析 + 应用后再并回"载入期间用户放的音符" |
| 背景图 | 全尺寸解码（可能几十 MB），每帧缩放并 new RectF | 按屏幕尺寸 `inSampleSize` 降采样，RectF 复用 |
| 框选 / Autoplay 命中 | 每个音符都算一次姿态（带排序） | 姿态移到循环外 |
| 点选音符 `findNoteAt` | 每音符 `noteScreenPos`（2 个数组 + 2 次排序） | 预先算好中心/旋转，纯算术 |

基准（JVM，`AlgosTest` / `DraftCodecTest` 打印）：

```
双押检测  1000 音符  8.2ms → 0.043ms   (×190)
双押检测  3000 音符 40.5ms → 0.169ms   (×239)
双押检测 10000 音符 468.8ms → 0.459ms  (×1021)
判定线插值 6000 次/帧 3.06ms → 0.42ms  (×7)
草稿编码 1 万音符 25.5ms → 5.0ms (×5)，解码 30.9ms → 16.1ms，体积 574KB → 258KB
```

> 关于"按可视区裁剪音符"：评估后没做。姿态计算提到循环外以后，屏幕外音符只剩两次乘法 + 一次比较
> （1 万音符约 0.1~0.3ms/帧）；而 `selectedSet`/`judgedIdx`/`holdFxList` 都按下标引用音符，
> 对 `notes` 重排会牵连一片；长条 Hold 又可能"起点在屏外、身体还在屏内"，按起点裁剪会漏画。
> 收益小而风险大，所以先不做。

## v0.20.1 标签逻辑修复（导入不再清空、删标签不再误删）

**1. 导入谱面会清空所有标签**
`applyImported` 里是 `tabs.clear(); tabs.add(t)`（早期"单项目模式"遗留）。现在导入结果
作为**新标签**加入，已有标签一个都不动，导入完自动切到新标签。

**2. 删掉一个标签会把别的标签也删了**
`deleteTab` 的顺序反了：先 `tabs.removeAt(i)` 再 `saveCurrent()`。`saveCurrent()` 写的是
**界面上还没刷新的输入框**（也就是被删标签的内容），而此时 `tabs[current]` 已经指向
"顶上来"的那个标签 —— 等于把 A 的内容覆盖到 B 上，看起来就是"删一个把另一个删了"。
现在顺序固定为：`saveCurrent()` → `removeAt` → 算新下标 → `restore` → `saveTabs` → `renderTabs` → 清理文件，
下标计算抽到 `TabOps.afterDelete()` 并有穷举单测。

**3. 顺带修掉的三个同源隐患**
- **id 为空/重复会让多个标签共用同一份文件**：草稿是 `drafts/<id>.json`、素材是 `imported/<id>/`。
  旧数据里 id 为空时，`File(filesDir, "imported/")` 就是整个素材目录，删一个标签会把
  **所有**导入素材清空。现在 `loadTabs` 会给空/重复 id 补新的唯一 id，`purgeTabFiles` 只放行
  UUID 形态的 id（`TabOps.isSafeId`）。
- **选素材会写错标签**：原来结果回来时按 `current` 落位，界面被系统回收重建后 `current` 会变，
  素材就写到别的项目上。现在记录发起选择时的标签 id，按 id 落位。
- **离开界面不落盘**：新增 `onPause` 时 `saveCurrent() + saveTabs()`，避免被系统回收丢改动。

**4. 小改善**：标签名改完立刻刷新标签栏（不用切一下才变）。

测试：`app/src/test/java/com/piezmaker/TabOpsTest.kt`（下标穷举 + id 白名单）。

- **素材选择改为卡片按钮**：蓝色圆角卡片 + ♪ / ▣ 图标，不再是纯文字

## 核心流程

1. **设置页**（默认横屏）：选音频 + 选背景图，填曲名 / 曲师 / 谱师 / 难度 / BPM / **流速** / **判定线位置** / 横线数 / 竖线数
   - **横线数**＝时间量化精度：每拍分成几格，音符时刻会吸附到格点上（如 4 = 每拍 4 格 = 16 分音符）
   - **竖线数**＝位置量化精度：判定线左右分成几格，音符左右位置会吸附到格点上（如 8）
   - **流速**＝音符下落倍率（默认 1.0），写入判定线 speedEvents
   - **判定线位置**＝判定线在屏幕上的纵向百分比（0~100，默认 60），写入 moveYEvents；**注意 RPE 的 moveY 向上为正**，所以 40%（靠上）=+90、60%（靠下）=-90。录制界面判定线同步画在该位置，所见即所得
   - **延迟**＝自动校准或手填（ms）。点「延迟校准」后听到「嘀」就点屏幕，共 10 次，取中位数作为建议值；导出时音符时间统一减掉这个延迟
2. 点「开始录制」→ 音乐播放，进入音游界面（背景图 + 判定线 + 网格）
3. **跟着音乐敲击**（支持多指同时）：
   - 快速点按 → `Tap`
   - 长按（≥280ms）→ `Hold`
   - 按住左右滑动超过 1 个竖线格 → `Hold`（滑动 hold）
   - 上下滑动 / 轻微左右滑动（不超过 1 个竖线格）→ `Flick`
4. 「导出 .pez」→ 系统保存对话框选位置，得到可在 Phira / RPE 中打开的谱面包

## 实时反馈

录制界面每帧持续刷新：按下的手指**立刻**在判定线对应格点渲染音符预览（点按为青色光圈，按住超过阈值后长出橙色 hold 条），松手即落成正式音符，不会出现"按了没反应"。

## 素材兼容（v0.2.0 修复）

- **图片**：任何格式（jpg/webp/gif/bmp 等）一律**解码重编码为真 PNG** 再打包，
  从根本上杜绝「内容与 .png 头不匹配」——即使系统给的文件名是 `image_xxx.png` 而实际字节是 JPEG
- **音频**：按**魔数嗅探**真实格式命名（OggS→ogg、RIFF/WAVE→wav、ID3/FFFB→mp3、ftyp→m4a、fLaC→flac），
  不再轻信文件名后缀

## 关于"横线竖线"

按你的定义：**竖线垂直于判定线方向，限制音符左右偏移**（位置量化）；
**横线是时间轴量化**（每拍分几格）。你要求"横线间距随 BPM 变化"——已按你的要求**不做**，横线为固定网格。

## 导出的 PEZ 结构（格式已与 Phira 源码交叉验证）

```
chart.json        # RPEJSON：META + BPMList + 单条判定线 judgeLineList
info.txt          # RPE 标准：# 开头 + Name/Song/Picture/Chart/Level/Composer/Charter
music.*           # 音频原样打包
bg.*              # 背景图原样打包
```

- RPE note type：`1=Tap 2=Hold 3=Flick 4=Drag`（与 Phira `prpr/src/parse/rpe.rs` 一致）
- 时间单位 beat：`beat = 秒 × bpm / 60`，量化到 `1/横线数` 拍，Triple 表示 `[i,n,d] = i + n/d`
- 延迟校正：导出前 `note.startMs -= delayMs`（把因设备延迟而记晚的音符拉回）
- 坐标：positionX 范围 `[-675, 675]`（解析端除以 675 归一化），量化到 `1/竖线数` 格
- 判定线：单条，`Texture: "line.png"`（Phira 内置 Normal 线，无需贴图资源）

## 签名

`piez-key.jks` 和 `keystore.properties` 都已被 `.gitignore` 排除，不进仓库。
`app/build.gradle` 从项目根的 `keystore.properties` 读取：

```properties
storeFile=piez-key.jks
storePassword=******
keyAlias=piez
keyPassword=******
```

文件缺失时 `assembleRelease` 仍能出包，只是产物未签名。**这两个文件要单独备份**——
